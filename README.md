# 霜焰双行（Frostfire Sanctum）

纯前端双人协作解谜平台跳跃。同一画面控制焰行者与霜行者，用水火对立规则、时序机关和场景可读线索过关。视觉走风格化写实，不用像素块堆角色或地图。

**当前状态：第 1–5 关可玩。** 24×14 横向单屏，包含阶梯折返、分色符文与晶石、潮位推箱、烧桥、反相门和循环齿轮。第 6–18 关仍为规划。

本轮玩法、空间比例与验收见 [1–5 关玩法与布局](docs/1-5关玩法与布局.md)。

默认跑速进一步下调 20%（烬 240、朔 232px/s），起步更柔和，跳跃节奏放缓但保留满跳高度和稳定跑动时的跨越距离。操作支持短加速/刹停、S / ↓ 精准慢行和长短跳；后段关卡加入可恢复碎裂悬台与时序窗口。寒气区和地面热汽喷口使用不同边界、标识及角色提示，详见 [操作手感与机关反馈](docs/操作手感与机关反馈.md)。

闸门统一收窄为 24px 的金属栅格，门扇在框内分向收回，不再用整块长门贴图跨层滑动；跳跃顶点共用稳定姿态，下落不再切入蜷缩末帧。拦截高度、开门条件和跳跃物理参数保持不变。

## 技术选型（已定）

- React 19 + TypeScript + Vite：站点壳、菜单、HUD、结算
- PixiJS 8：高分辨率精灵、材质贴图与机关状态绘制
- 自研固定时间步物理：平台跳跃手感与元素规则，不依赖 Arcade/Matter 作为玩法真相
- 关卡 TypeScript 数据驱动；进度存 `localStorage`，导出/导入尚未实现
- Dokploy：多阶段 Docker 构建 + Caddy 静态托管 + `/healthz`

## 启动

```bash
./scripts/dev.sh      # 开发，默认 5173
./scripts/start.sh    # 构建并预览，默认 4173
npm test              # 逻辑层测试（不启动页面）
```

烬：`WASD` + `J`。朔：方向键 + `;`。`Esc` 暂停，游玩中长按 `R` 0.4 秒重开，暂停/结算时点按重开。收齐双符文才能开启出口；三星额外要求全部 6 件收集物。

Dokploy：Git 应用 + 仓库根 `Dockerfile`，容器端口 **3000**，健康检查 `/healthz`，不要把 3000 映射到公网。步骤见 [docs/部署运维.md](docs/部署运维.md)。
