## 本次浏览器验证

使用本地 Vite（5175）、Playwright Chromium。当前会话没有 Browser 插件，所以使用已安装的 Playwright；未安装新项目依赖。测试档在隔离浏览器上下文中临时解锁五关，不修改真实玩家存档。

- 1440×900：逐关载入、提示展开、暂停后时钟不变、继续、失焦自动暂停、键盘移动、Space 激活提示按钮、重开清零收集、返回选关。
- 1280×720、390×844、844×390：完整舞台、页面无横向溢出、按钮可访问。相机 fit 另有数值断言。
- 页面标题、非空内容、无 Vite 错误覆盖、控制台/页面异常、HUD 与舞台边界均检查。
- 保存五关、选关和响应式截图用于复核；截图文件不是构建依赖，也不入 Git。
- 1280×720 串联回归：在隔离页面接入现有输入回放策略，保留真实 Runtime 固定步进、渲染和存档，依次通关 1→5；每关显示三星 / 6 件收集物，前四关“下一关”有效，第五关无该按钮，回选关后五关成绩保留。不是声称人工双手玩通。
- 已确认 Pixi ticker 未自启动，避免与 Runtime 的手动绘制形成双循环。初测在软件渲染环境中第三关到 12.7s 模拟时间时触发 70s 测试等待超时；移除重复绘制并延长合理的测试等待窗口后，串联回归通过。未用这一结果宣称真实设备帧率。
- 第二轮第 5 关使用 Playwright 的真实键盘事件（非 demo），从出生点移动烬触发齿轮、留在接应板；朔在首闸外故意错过开门，等后续周期再跳入中室取符文，通过末闸并双人到出口。结果 0 死、5/6 收集、两星；未取左侧可选晶石，未修改模拟坐标或拾取状态。对应路线另由 `InputMap` 输入回归固定下来。
- 第二轮响应式检查发现 844×390 下目标栏与舞台顶部重叠 4px；横屏舞台上边距由 80px 改为 88px，不通过放宽断言掩盖重叠。
- 修正后再次验证 1280×720、390×844、844×390：无横向溢出，舞台不与目标栏/底栏重叠。再次逐关运行真实 Runtime + 输入回放，五关均为 0 死、6/6、三星，控制台及页面异常列表为空。第二轮截图与结果位于本机临时 QA 目录，不作为源码或构建依赖。

**视觉验收限制**：当前会话的图像查看工具拒绝图像输入，因此虽已生成真实截图、验证 DOM 和布局几何，不能宣称完成逐像素人工视觉签核或对概念图的 10/10 还原。未使用图像生成，也未复制外部位图。

## 真人试玩清单

1. 第一关朔攀三层梯、跳支路、返回底道；烬跨阁楼断口并诱敌；两人踩门板和等待蒸汽。
2. 第二关先取符文再推箱升潮，注意深水与中水区别；确认限时出口允许两人会合。
3. 第三关烬取阁楼符文，从高踏台跨井；朔先过桥再由烬点燃，不能忽略烧桥直接开门。
4. 第四关攀较高折返梯，经左悬台返回底道，再在内环切换闸门；第五关故意错过一次水闸，等下一周期进入中室，跳上石台取冰符文，左侧普通晶石可不取。
5. 双人到达各自出口才能结算，下一关正常进入，第五关无虚假下一关。
6. 失焦暂停；救援中反复暂停不延长救援；键盘 Tab/Enter/Space 可操作按钮。
7. 小屏不裁掉角色与出口；提示不常驻遮挡；系统减少动态效果不改变危险周期。
