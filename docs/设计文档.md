# 设计文档

更新：2026-09-22。供架构 / 实现维护者使用，仅描述当前实现。玩法与布局详见 [1–5 关玩法与布局](./1-5关玩法与布局.md)。

## 目标和范围

纯前端同屏双人解谜，当前 1–5 关。用分色收集、元素危险区和接力机关让每段平台具有用途。保留已有写实角色和材质；不复制参考游戏的地图或美术。6–18 关、账号、联机、触屏操控不属于已实现范围。

## 架构与技术选择

沿用 React + TypeScript + Vite 的页面壳、PixiJS 8 的精灵渲染和自研固定步进物理，不引入第二套游戏引擎或新依赖。Pixi 的必要性是已有精灵帧、贴图平铺和多层动态图形；简单选关预览采用 SVG，无需建立额外 Pixi 实例。

```text
键盘 / UI按钮 → InputMap / GameRuntime
                      ↓ 1/120s
LevelDocument → createSim → stepSim → SimState
                                      ├→ GameView（每帧，读取状态）
                                      ├→ HudModel（最多 10Hz，React）
                                      └→ recordClear（通关一次，localStorage）
```

- UI 不负责物理判定；模拟层不依赖 DOM。
- 渲染循环由 GameRuntime 单独拥有；Pixi 初始化使用 `autoStart: false` / `sharedTicker: false`，避免默认 ticker 与手动 `app.render()` 重复绘制。
- `solidsNow` 是当前实体碰撞的统一入口，合并静态地形、门、潮位浮冰、桥与灰烬。
- `activeHazards` 合并固定危险区和潮位危险区。
- `holdGateOpen` / `gearWindowOpen` 供碰撞与渲染共同使用，避免门已开但外观仍关闭。
- `runesReady` 为开闩和通关共同检查，收集进度位于 `SimState.collected`，不是 DOM 状态。
- `roomGuidance` 从同一 `SimState` 派生任务与机关倒计时，随 HUD 最多 10Hz 更新，不引入另一套倒计时钟或玩法状态。
- `interactions` 共用交互范围与点燃判定，派生角色操作提示并记录短确认文案；`fragile` 维护碎裂踏台状态，`solidsNow` 只包含未消失踏台。
- `animation` 在模拟步末根据碰撞、推箱和机关结果更新动作；`view/actorPose` 将动作映射到既有帧，避免显示层创建第二套运动逻辑。`view/hazardVisuals` 限制蒸汽粒子范围/数量，危险区仍由原矩形判定。
- 回放使用 WeakMap 记录每个模拟实例的输入导航进度；新实例自动从头开始，不污染关卡定义或存档。

## 房间与显示契约

24×14 格，48px/格；完整单屏 fit。角色碰撞 22×34px、精灵高 50px；平台顶面和精灵脚底必须与碰撞面一致。相机只使用舞台实际尺寸，不依赖固定的桌面最小宽高。

五关分别配置阶梯轮廓：左折返、右起左返、右上连续梯、较高折返与左悬台、可选折返加时序中室符文台；第三/四关另有火侧阁楼取符文路线。两枚符文构成必走路径，额外晶石形成支路目标。按住门、第四关水相闸和第五关下层齿轮门增高，防止新增高台绕过核心协作。

HUD/目标栏/操作条位于舞台外；背景等比缩放，降低对比。已有位图继续承担角色、墙体、地台和门的主体视觉；代码图形只表达顶边、晶石、符文、机关状态等。

## 核心状态与失败模型

- paused、failed、cleared 不推进物理钟。失焦自动暂停并清键；暂停救援窗后恢复原状态，不能重复得到 8 秒救援时间。
- 单人倒地允许 8s 内祭坛救援；关键资源失败时进入 UI 错误态，可返回选关。
- 第五关齿轮时间按 `cycleMs=10000` 取模，错过窗口是等待成本，不是永久软锁。
- 关闭按住门/已启动齿轮门前检查门洞内角色和箱子，未离开不恢复碰撞；终点闩门保留原有角色防夹规则。
- 第三关油桥未塌时拒绝开闩，保证点燃规则不能被忽略。
- 第三/四关可选悬台触发后不可取消坍塌，但会恢复；恢复位置被角色/箱子占用则延迟，避免新实体穿入角色。相位板一次持续踩住只触发一次。
- 移动加速、精准慢行、跳跃容错与下降重力参数见 [操作手感与机关反馈](./操作手感与机关反馈.md)。三星目标缩短不引入强制超时失败。
- 非关键动画加载失败用已加载静态帧继续；资源缓存由 Pixi 管理。重开销毁旧静态场景节点，保留复用的压板/祭坛节点和共享纹理。

## 数据与兼容

关卡真相为 TypeScript `LevelDocument`，不是历史 JSON。存档仍为 `frostfire.sanctum.v1`，没有迁移或清空玩家进度。新评分适用于本次重玩；历史最高星级只升不降。收藏只属于单局，不新增持久化字段。

实际字段见 [数据模型](./数据模型.md)，函数边界见 [接口文档](./接口文档.md)。

## 测试、运行与演进边界

`tests/room-layout.test.ts` 验证五关全收集零死亡三星、相机 fit、出生点、门禁、烧桥前置、齿轮循环、防夹和评分；原有伤害、跳跃、蒸汽、残烬、门闩测试保留。`tests/runtime.test.ts` 覆盖暂停救援状态与清键。

`tests/guidance.test.ts` 验证第五关提示顺序、时序窗口/防夹倒计时、蒸汽与烧桥时间、深潮开门后的降潮提示，以及救援优先级；布局测试同时检查五种支路不是平移复制、第五关符文必须在中室拾取、第四关不能跳过关闭的水相闸。

`tests/movement.test.ts` 覆盖双角色左右方向的跑速上限、单位时间位移、慢行切换/释放、加速/刹车、跳跃高度/土狼时间和动作时钟；`tests/interaction-variety.test.ts` 覆盖碎裂/恢复/暂停/防夹、换相防重复、倒地拒绝交互、确认文案和难度配置；`tests/hazard-readability.test.ts` 覆盖热汽粒子边界、阶段文字、角色区别提示和既有伤害矩阵不变。

运行命令见 [开发文档](./开发文档.md)，测试证据及未覆盖风险见 [测试文档](./测试文档.md)，交付环境见 [部署运维](./部署运维.md)。部署脚本、容器、路由和资源供应链本次不变，没有执行发布。

以后新增复杂运动平台或冻融机制，应同时扩展类型、模拟、渲染、作者数据和失败回放，不能只画出一个没有碰撞/状态真相的机关。移动端目前仅保证完整显示和菜单可操作，需真实触屏输入设计后才能宣布可触屏游玩。
