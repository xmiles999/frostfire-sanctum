# 部署运维

## 1. 形态

纯静态 SPA。Dokploy 用 Dockerfile 构建 `dist/`，Caddy 在 3000 提供文件与 `/healthz`。无数据库、无运行时环境变量玩法依赖。

**当前限制：** Dockerfile / Caddyfile / compose 尚未进仓库，下文是阶段 E 必须落地的目标配置。Plan 阶段不要当已上线。

## 2. 目标 Dockerfile

```
FROM node:22-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . ./
RUN npm run build

FROM caddy:2.10-alpine
COPY Caddyfile /etc/caddy/Caddyfile
COPY --from=build /app/dist /app/dist
RUN addgroup -S app && adduser -S -D -H -G app app \
  && mkdir -p /config/caddy /data/caddy \
  && chown -R app:app /app /config /data
USER app
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=15s --retries=3 \
  CMD wget -q -O /dev/null http://127.0.0.1:3000/healthz || exit 1
CMD ["caddy", "run", "--config", "/etc/caddy/Caddyfile", "--adapter", "caddyfile"]
```

说明：Dokploy 所用 Caddy 镜像可能无 `caddy` 用户，故自建 `app` 用户，与工作区 `audio-convert` 一致。

## 3. 目标 Caddyfile

```
:3000 {
  route {
    encode gzip
    header {
      X-Content-Type-Options "nosniff"
      Referrer-Policy "strict-origin-when-cross-origin"
    }
    respond /healthz "ok" 200
    root * /app/dist
    @versioned { path /assets/* }
    header @versioned { Cache-Control "public, max-age=31536000, immutable" }
    @html { path *.html }
    header @html { Cache-Control "no-cache, no-store, must-revalidate" }
    try_files {path} /index.html
    file_server
  }
}
```

`/healthz` 必须在 `try_files` 之前，避免被 SPA 吃掉。

## 4. 目标 compose（Dokploy）

```yaml
services:
  frostfire-sanctum:
    build:
      context: ..
      dockerfile: Dockerfile
    restart: unless-stopped
    expose:
      - "3000"
    networks:
      - dokploy-network
    security_opt:
      - no-new-privileges:true
    healthcheck:
      test: ["CMD", "wget", "-q", "-O", "/dev/null", "http://127.0.0.1:3000/healthz"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 15s

networks:
  dokploy-network:
    external: true
```

文件计划路径：`deploy/dokploy-compose.yaml`。Dokploy 里网络名以实例为准，需与面板一致。

## 5. 启动 / 停止 / 健康

| 环境 | 入口 | 停止 | 健康 |
|---|---|---|---|
| 开发 | `./scripts/dev.sh`（阶段 B） | Ctrl+C | 浏览器 |
| 本地预览 | `./scripts/start.sh` | Ctrl+C | 浏览器 |
| 生产 | Dokploy 部署该镜像 | 面板 Stop | `GET /healthz` → `ok` |

权限：构建需仓库读权限；运行用户非 root。无密钥。

## 6. 失败退出

- 无 lockfile：`npm ci` 失败
- `tsc` 或 vite 失败：不产出残缺 dist
- 容器内 healthz 连续失败：编排器重启

重复部署：不可变镜像，幂等。

## 7. 回滚

Dokploy 保留上一镜像 tag。回滚即切回上一成功部署。存档在用户浏览器，回滚服务不影响存档；若新版升了 `version` 且不兼容，必须在数据模型提供迁移或拒绝加载并保留备份。

## 8. 阶段 E 验证清单（届时执行，现不跑服务）

- 正常构建镜像
- healthz 200
- 重复部署不产生脏卷依赖
- 故意去掉 Caddyfile 构建失败
- 不测：证书、域名 DNS
