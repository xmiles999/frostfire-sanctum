# 部署运维

## 1. 形态

纯静态 SPA。Dokploy 用仓库根目录 `Dockerfile` 多阶段构建 `dist/`，Caddy 在容器内 **3000** 提供文件与 `/healthz`。无数据库、无运行时密钥、无玩法环境变量。

| 文件 | 用途 |
|---|---|
| `Dockerfile` | 构建 + 非 root Caddy |
| `Caddyfile` | `:3000`、SPA `try_files`、`/healthz` 先于回退 |
| `.dockerignore` | 排除 `node_modules`、`.scratch` |
| `deploy/dokploy-compose.yaml` | 可选 Compose 模板 |

推荐用 **Git + Dockerfile 应用**（与 `homepage` / `audio-convert` 相同），不要把 3000 发到宿主机公网。TLS 交给 Dokploy/Traefik。

## 2. 发布前

1. 把含 `Dockerfile` 的提交推到 `main`：`git@github.com:xmiles999/frostfire-sanctum.git`
2. 本地可先：`npm test`（不强制起开发服务器）
3. 记下当前线上部署（若已有）以便回滚

本仓库进度存 `localStorage`，回滚镜像不影响玩家存档。

## 3. Dokploy：Dockerfile 应用（推荐）

1. **Create Application** → 选 **Git** 提供者，仓库 `xmiles999/frostfire-sanctum`，分支 `main`。
2. Build 类型选 **Dockerfile**（不要 Nixpacks）。
3. 填写：
   - Build path / context：`.`（仓库根）
   - Dockerfile：`Dockerfile`
   - 容器端口：**3000**
   - 健康检查路径：`/healthz`
4. **不要** 配置 Host 端口映射（不要 `3000:3000`）。让应用加入 Dokploy 默认网络，由 Traefik 反代。
5. Domains：加你的域名（或 Dokploy 预览域），开启 HTTPS/Let's Encrypt。
6. 环境变量：可不填。
7. Deploy。首次会 `npm ci` + `vite build`，素材较多，构建可能要几分钟。
8. 日志里应出现 Caddy 监听；健康检查变绿。

 Traefik 标签一般由 Dokploy 自动加。若你手动管网络，把服务挂到面板里的 `dokploy-network`（名称以实例为准）。

## 4. Dokploy：Compose（可选）

1. Create → **Docker Compose**。
2. Compose 文件路径：`deploy/dokploy-compose.yaml`。
3. 该文件 `build.context` 为 `..`，假定工作目录是 `deploy/`。若面板以仓库根为工作目录，把 context 改成 `.` 后再部署。
4. 网络 `dokploy-network` 必须已存在且为 external；名称必须与面板一致。
5. 同样只 `expose: 3000`，不 publish 80/443。
6. 域名仍在 Dokploy Domain 里绑到该服务。

## 5. DNS 与 TLS

1. 域名 A/AAAA 或 CNAME 指到 Dokploy 主机（或已有入口）。
2. 在面板给应用加 Domain，开启证书。
3. 验证：

```bash
curl -fsS https://你的域名/healthz
# 期望：ok

curl -fsSI https://你的域名/
# 期望：200，text/html
```

打开首页应能进「裂隙初醒」。未知路径由 Caddy 回退到 `index.html`。

## 6. 更新与回滚

- 更新：推 `main` 后在 Dokploy 里 Redeploy（或开 Auto Deploy on push）。
- 回滚：面板选上一成功部署/镜像。不要靠改玩家浏览器存档。
- 失败常见原因：
  - 还在用 Nixpacks → 改 Dockerfile
  - 端口填成 80/5173 → 必须 3000
  - `/healthz` 被 SPA 吃掉 → 确认用了本仓库 `Caddyfile` 的 `route` 顺序
  - Compose 的 `dokploy-network` 名字不对 → 在面板 Networks 里核对

## 7. 停止与权限

| 动作 | 方法 |
|---|---|
| 停止 | Dokploy Stop |
| 启动 | Start / Redeploy |
| 健康 | `GET /healthz` → `ok` |
| 权限 | Git 读权限即可；镜像内 `USER app` 非 root |

## 8. 当前限制

- 阶段 B 只含第 1 关；上线后即可玩竖切，不是 18 关成品。
- 未在本机执行 Docker 构建（按习惯不擅自起服务）。首次 Dokploy 构建即验证镜像。
